# 기후안심지도 · ClimateGuard

SGIS 공간통계와 기상청 관측자료로 부산의 상대적 폭염 취약성과 부산시 공식 침수 자료를 살펴보는 지도형 MVP입니다. FastAPI가 지표와 점수를 계산하고, Next.js·MapLibre가 지도를 표시합니다. 통계 설명은 계산 결과를 그대로 사용하며, 동별 대응 설명은 공식 자료에 연결한 항목을 로컬 Qwen으로 미리 작성해 제공합니다.

## 현재 구현 상태

- 왼쪽 상단의 **폭염 / 침수** 전환과 동네 이름 검색을 제공합니다. 지역 선택은 바로 반영됩니다.
- **침수**는 과거 이력 186건의 지점·발생 기간·깊이·면적과 강우 조건별 공식 예상도를 별도 탭으로 제공합니다. 예상도는 30·50·80·100년 빈도 조건을 선택하며 실시간 상황이나 폭염 취약도와 섞지 않습니다.
- 통계·경계 연도는 데이터 안내에서 확인하고, 주 화면에는 관측일·사건 발생일처럼 해석에 필요한 시점을 표시합니다.

- 첫 화면은 **부산 전체 읍면동 우선 대응지역**입니다. 동별 순위와 상세 분석은 왼쪽 작업 패널에서 전환하며, 오른쪽은 지도 공간으로 사용합니다.
- 지도 축척에 따라 **구·군 ↔ 읍·면·동 이름·경계가 자동 전환**되며 동별 우선순위는 유지됩니다.
- 위험현황에는 **2024년 6~8월 일별 최고·최저 기온 그래프와 기간 극값**을 펼쳐 볼 수 있습니다. 점수 계산은 기존 평균기온·폭염일수를 유지합니다.
- **대응방안 / 보고서** 탭에서 동별 우선순위·선정 근거와 함께 대응의 초점, 먼저 할 일, 실행 제안·협의 대상·점검 결과·공식 출처를 읽고 저장합니다. 해당 동의 현재 시설을 확인한 뒤 보고서로 돌아올 수 있습니다. 탭이나 동을 바꾸면 패널 위에서 읽기 시작합니다.
- **동네 분석 → 현재기상**에서도 선택한 동의 인근 관측소 기록을 확인합니다. 위험현황 상단에는 최신 최고·최저 요약, 현재기상 탭에는 최근 30일·올여름 그래프를 표시합니다. 관측소명·거리·관측일을 함께 표시하며 2024년 점수와 구분합니다.
- **기상 비교** 지도에서 같은 관측일의 관측소별 최고기온을 비교합니다. 관측소 선택 → 연결된 동 목록 → 동네 분석으로 이동하며, 동네 분석의 현재 기온 카드에서도 해당 관측소 지도로 돌아갈 수 있습니다. 최근 30일·여름 기록과 갱신 기능도 유지합니다.
- **현재 시설**에서 쉼터·그늘막 위치와 이용대상·등록 운영요일·시간을 확인합니다. 운영정보가 없는 시설은 별도로 표시합니다.
- **취약도 지도 / 상세 도로지도** 전환을 제공합니다. 도로지도 출처는 OpenStreetMap이며 현재 시설은 별도 화면에서 2026년 쉼터 1,735개·그늘막 1,834개 위치를 보여줍니다. 2024년 취약도·인구와 수치 비교하지 않습니다.

- 대한민국 시도 → 전국 시군구 → 읍면동 경계 탐색. 부산 외 경계는 첫 조회 시 SGIS에서 받아 캐시합니다.
- 부산 **16개 구·군 / 206개 읍면동**, 부산 전체 포함 **223개 실제 통계 레코드**.
- **2024년 통계 + 2025년 SGIS 경계**. 녹산동·신호동 코드 정합성을 확인했으며 두 연도 사용은 사용자 승인사항입니다.
- 실제 확보 지표: 여름 평균기온, 여름 폭염일수, 총인구, 인구밀도, 65세 이상 인구 비율, 1인가구 비율, 30년 이상 노후주택 비율.
- **실제 종합점수 산출: 구·군 14/16개, 읍면동 173/206개.** 최근접 기상청 관측소에 결측일이 있는 지역은 점수를 비워 둡니다. 누락값을 0이나 평균으로 채우지 않습니다.
- 기상은 2024년 6~8월의 인근 관측소 기준이며 해당 동 자체의 실측값이 아닙니다. 관측소명·거리·유효 관측일수를 표시합니다.
- 모든 운영 수집기의 외부 요청은 호스트별 최소 3초 간격이며, 여러 로컬 프로세스에도 적용됩니다. HTTP 429에는 Retry-After(없으면 30초)를 적용합니다.
- Sample은 별도의 합성 통계이며 7개 지표, H/E/V, 5등급, Top 3·Top 5, 지도 연동, 비교 차트, 대응방안을 모두 실행할 수 있습니다. 화면 전체에서 Sample임을 표시합니다.
- SGIS 인증키는 백엔드 `.env`에만 존재하며 브라우저로 전달하지 않습니다.

## 실행

Python 3.11 이상, Node.js 20.9 이상이 필요합니다. 이 환경에서는 Python 3.14 / Node.js 24로 검증했습니다.

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.lock.txt
npm --prefix frontend ci
```

`.env`가 없는 새 환경에서만 `.env.example`을 `.env`로 복사하고 키를 입력하세요. 기존 `.env`를 덮어쓰지 마세요.

```dotenv
SGIS_SERVICE_ID=발급받은_서비스_ID
SGIS_SECURITY_KEY=발급받은_보안키
DATA_MODE=sgis
```

실제 자료 수집은 서버 실행과 별도로 한 번 수행합니다. 이후 통계 화면 조회는 로컬 스냅샷을 사용합니다.

```sh
.venv/bin/python scripts/collect_sgis.py
.venv/bin/python scripts/collect_kma.py
.venv/bin/python scripts/collect_housing.py
.venv/bin/python scripts/enrich_actual.py
.venv/bin/python scripts/collect_kma.py --extremes
.venv/bin/python scripts/collect_shelters.py
.venv/bin/python scripts/prepare_facilities.py
.venv/bin/python scripts/collect_kma.py --current
.venv/bin/python scripts/collect_flood.py
./run_app.sh --port 3018 --api-port 8018
```

- 웹: http://127.0.0.1:3018
- API 명세: http://127.0.0.1:8018/docs
- 종료: 실행 터미널에서 `Ctrl+C`. 이 스크립트가 시작한 두 서비스만 종료합니다.
- 포트를 생략하면 웹 3000 / API 8000입니다. 다른 서비스가 사용하는 포트는 종료하지 않고 별도 포트를 지정하세요.

키가 없는 환경의 기능 테스트:

```sh
./run_app.sh --mode sample --port 3018 --api-port 8018
```

저장소의 `data/sample/`에는 실제 SGIS 경계와 별도로 생성한 합성 통계가 있습니다. 실제 통계 캐시는 `data/processed/sgis.json`에 있으며 Git에서 제외됩니다. 실제 모드의 인증·캐시 문제가 발생해도 자동으로 합성 통계로 바꾸지 않습니다. 화면의 명시적인 Sample 전환을 사용하세요.

원본 캐시 갱신과 Sample 재생성:

```sh
.venv/bin/python scripts/collect_sgis.py --refresh
.venv/bin/python scripts/collect_kma.py --refresh
.venv/bin/python scripts/collect_housing.py --refresh
.venv/bin/python scripts/enrich_actual.py
.venv/bin/python scripts/build_sample.py
```

## 사용 흐름

1. 첫 화면의 부산 전체 동별 우선 검토 순위에서 동을 선택하거나 지도를 확대해 읍·면·동을 선택합니다.
2. 실제 모드에서 **종합 위험도와 Top 5**, H/E/V 및 7개 개별지표 분포를 확인합니다. 회색 지역은 결측으로 점수를 산출하지 않은 지역입니다.
3. 지역 Polygon 또는 이름을 클릭하면 데이터보드와 선택 강조가 갱신됩니다.
4. ‘읍면동별 자세히 보기’ 또는 Polygon 더블클릭으로 내려갑니다. 상단 경로로 돌아갈 수 있습니다.
5. 왼쪽 위험현황 / 원인분석 / 대응방안 / 보고서 탭에서 일별 최고·최저, 분석 근거와 대응을 확인합니다. 보고서는 입력 없이 자동 생성되며 파일로 저장할 수 있습니다.
6. Sample 모드에서 종합 점수·순위·H/E/V의 전체 시연 흐름을 확인합니다. Sample 순위를 실제 정책 판단에 사용하지 않습니다.

데이터보드·범례·레이어 버튼, 지도 확대·축소·초기화, 지역 선택, Top 5 클릭이 동작합니다. 침수는 별도 자료 화면을 제공하며, 산사태·태풍은 미구현입니다. Desktop 우선 UI이며 권장 화면 너비는 1280px 이상입니다.

## 동별 보고서 준비와 배포

Ollama에 이미 설치된 `qwen2.5:7b`를 사용합니다. OpenAI 키, 유료 API, 모델 다운로드는 사용하지 않습니다.

```sh
.venv/bin/python scripts/prepare_reports.py --dry-run
.venv/bin/python scripts/prepare_reports.py --limit 3
.venv/bin/python scripts/prepare_reports.py
```

- 현재 스냅샷의 산출 가능한 **173개 동**에 대응 설명을 준비했습니다. 자료가 부족한 33개 동과 Sample은 생성 설명을 사용하지 않고, 확보한 지표·대응 원칙을 보여줍니다.
- 점수·수치·비교·순위는 기존 계산 결과이며 모델이 작성하지 않습니다. 공식 자료를 검토한 대응 Catalog는 7개 지표를 모두 포함합니다. 모델은 선정된 대응 항목의 실행 순서를 한국어로 정리합니다.
- 공식 자료는 행안부의 2026년 여름철 자연재난 종합대책과 그늘막 확충 자료입니다. 링크·근거 문구는 검토한 Catalog에서 제공하고 모델이 만들지 않습니다. 실행 단계·협의 대상·점검 결과는 지역 적용을 위한 제안입니다.
- 동일한 대응 항목·순서·모델·프롬프트는 작성 문장을 재사용합니다. 동별 통계, 순위, 연결 지표와 보고서 입력 검증값은 각각 유지합니다. 따라서 유사한 동은 대응 설명이 같을 수 있습니다.
- 배포 산출물은 `data/reports/heatwave/*.json`이며 Git 제외 대상이 아닙니다. 통계·출처·대응 항목이 바뀌면 입력 검증값이 달라져 예전 설명을 숨기고, 다음 생성 때 갱신합니다. 조회 중에는 생성하지 않습니다.
- 원본 모델 응답과 재사용 캐시는 `data/raw/reports/`에 저장됩니다. 숫자·링크·수치 비교·확정적 표현 등 기본 검사를 통과한 설명만 저장합니다. 이는 사실성의 완전한 보증이 아니므로 프롬프트나 자료를 바꾸면 생성 결과를 다시 검토해야 합니다.
- 실제 Ollama 호출은 최소 3초 간격입니다. `--code`를 반복해서 특정 동만 준비하거나 `--refresh`로 재생성할 수 있습니다. 요청 실패나 검증 거절은 정상 파일을 덮어쓰지 않습니다.
- 배포 서버에는 **Qwen·Ollama가 필요 없습니다.** 저장한 JSON을 API와 함께 배포합니다. 현재 FastAPI·실제 데이터 파일의 배포 및 저장·갱신 구성은 별도이며, 이 변경에서 Vercel 배포를 수행하지는 않았습니다.

보고서 전용 브라우저 검증: `cd frontend` 후 `node tests/e2e.mjs --reports-only`.

## 계산과 설명

`config/risk_weights.yaml`에서 PRD 가중치를 변경할 수 있습니다. 각 그룹의 가중치 합은 1이어야 합니다.

```text
지표 정규화 = (값 - 비교지역 최솟값) / (최댓값 - 최솟값)
H / E / V = 그룹별 정규화 값의 가중합
RiskRaw = H × E × V
RiskScore = MinMax(RiskRaw) × 100
```

API의 H/E/V 표시 점수는 가중합 × 100입니다. 모든 지표가 있어야 종합 점수를 산출합니다. 기본 비교범위는 부산 전체 읍면동이며 구·군 요약 또는 선택한 구·군의 읍면동 비교로 전환할 수 있습니다. 축소 지도의 구·군 색상은 구·군끼리 비교한 값이고 왼쪽 동별 순위는 그대로 유지됩니다. 범위가 다른 Risk Score는 직접 비교할 수 없습니다.

- 동일 지표 값: 정규화 0.5. 동일 RiskRaw: 50점 및 ‘차이 없음’ 안내.
- 구간: `[0,20)`, `[20,40)`, `[40,60)`, `[60,80)`, `[80,100]`.
- 주요 요인: 정규화 값 × 지표 가중치 상위 3개. 인과효과 추정이 아닙니다.
- 고령·1인가구 비교: 유효한 분자·분모 쌍의 합산 비율. 실제 노후주택 비교: SGIS 공식 상위지역 비율(수량 역산 없음). Sample 노후주택 비교: 합성 수량의 합산 비율. 인구밀도 비교 기준: 총인구 / 합산 면적(인구/밀도로 복원). 총인구·기후지표 비교 기준: 산술평균.
- `%p` 차이와 배수는 백엔드에서 계산하며 평균 0의 배수는 제공하지 않습니다.
- `/api/ai/explain`은 지역코드·비교범위·모드만 받아 서버의 결과를 문장화합니다. 클라이언트가 점수나 설명 수치를 주입할 수 없습니다.

npm --prefix frontend run test:e2e

브라우저 테스트는 이 환경의 macOS Chrome을 사용합니다. 다른 서버 주소는 `APP_URL`로 지정할 수 있습니다. E2E는 실제 SGIS 캐시와 전국 추가 경계 조회에 필요한 키가 있는 환경에서 수행합니다.

프로덕션은 API 주소를 빌드할 때 지정합니다. Next.js rewrite 목적지는 빌드에 포함됩니다.

```sh
cd frontend
BACKEND_URL=http://127.0.0.1:8018 npm run build
cd ..
./run_app.sh --production --port 3018 --api-port 8018
```

## 자료 수집과 한계

기상청 공개 조회 화면의 일 관측자료를 서버에서 캐시합니다. 현재 수집에는 별도의 기상청 API 키가 필요하지 않습니다. 공식 API허브로 전환하려면 기상청 인증키가 별도로 필요합니다. 2024년 분석에 현재 날씨를 혼합하지 않습니다. 별도 현재 기상 화면은 2026년 일 관측기록을 제공하며 실시간 순간 기온은 제공하지 않습니다. 갱신은 어제까지 조회하며 최근 6시간 캐시를 재사용합니다.

기상자료는 관측소 지점값을 행정지역에 연결한 것입니다. 지역 내부 대표점(투영 좌표계의 면적 중심, 영역 밖이면 내부점)의 최근접 관측소를 사용합니다. 최근접 관측소에 결측이 있어도 더 먼 관측소로 자동 대체하지 않습니다. 2024년 여름 위치 이력을 확인한 부산 관측소만 후보로 사용합니다.

일 평균·최고기온 각각 92일이 모두 있어야 해당 지표를 계산합니다. 원자료가 보완되지 않는 한 일부 지역의 종합점수는 제공하지 않습니다. 모델 가중치의 실증적 검증, 전국 통계 분석, 실시간 날씨는 향후 확장입니다.

기존 `collect_sgis.py`만 다시 실행하면 기본 SGIS 자료로 돌아갑니다. 세 수집기 실행 후 `enrich_actual.py`로 결합하세요. 캐시는 Git에서 제외되며 `--refresh`를 지정하지 않으면 재사용합니다. 최초 기상 수집은 3초 요청 간격 때문에 수 분 이상 소요됩니다.
